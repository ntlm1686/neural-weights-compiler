# MinAtar model and compiler comparison

Results collected on 2026-11-03. All local scores use the repository's `minatar_envs.py` and `evaluate_game`, 200 episodes, seed 0, 0.1 sticky actions, softmax action sampling and a 10,000-step episode cap. Standard errors are over episodes from that seed. These scores are not comparable to the published evaluation as a controlled experiment unless the respective environments and protocols are independently shown equivalent.

The project owner identified the historical work as Gemini 4 Argon; the saved historical files do not independently record the agent's model. The earlier Argon policies' development/selection history is not fully available. The Seaquest and Asterix implementations directly create weight arrays and do not invoke NeuralCompiler, despite their function names. The earlier standalone edits are available only for Breakout.

The new Astra and Terra policies were generated by independent subagents with `fork_turns="none"`: they received the relevant prompt paths, and for the compiler condition the IR and backend file paths. They were instructed not to read existing policy or result files, run code, train, perform model forward passes or receive rollout feedback. Generated code was transcribed into the policy files here without changing its logic, and scored by the parent afterwards. The Terra Breakout standalone agent returned a literal `edits` block; the Seaquest and Asterix standalone agent returned Python initialization code, so the authoring format differs from the original text-only Astra setup. Seaquest and Asterix were given together to each model/condition agent, so those two tasks did not have independent conversation contexts. The history-free context still includes normal system instructions and model pretraining. Each new cell is a single generated policy and does not measure run-to-run variability.

The Breakout prompt is `../../blind_tasks/exp5_breakout_prompt.txt`; the Seaquest and Asterix prompts are the included files generated by extracting the local environment class and observation mapping. Compiler agents additionally read the package IR and backend. Original published GPT-6 Astra scores are 517.4, 53.1 and 53.2, respectively, from [Sparks of Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/); those are 1,000-episode paper results, not locally rerun scores.

Reproduce a local entry from the repository root:

```bash
export OPENBLAS_NUM_THREADS=1
python experiments/minatar_model_comparison/evaluate.py experiments/minatar_model_comparison/terra_alone_breakout.txt --game breakout
python experiments/minatar_model_comparison/evaluate.py experiments/minatar_model_comparison/terra_compiler_seaquest.py --game seaquest
python experiments/minatar_model_comparison/evaluate.py results/exp5_subagent_response.md --game breakout
```

## Local Qwen3.8-27B

The model was restored from the user's existing HDFS archive; all 18 shards were checked against the archived SHA-256 manifest. Snapshot revision: `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`. Local inference used vLLM 0.31.0, BF16 on one H100 80 GB, text-only mode, temperature 0, `enable_thinking=False`, and 4,096 maximum output tokens. Each of the six task/condition prompts was sent in its own independent conversation in one batch, with no gameplay feedback. The Breakout standalone prompt asks for literal edits; for the other tasks standalone prompts ask for Python weight initialization. The Seaquest standalone response chose seeded random initial weights, so it does not meet the original Astra text-only weight-writing protocol.

| Condition | Breakout | Seaquest | Asterix |
| --- | ---: | ---: | ---: |
| Alone | 0.23 ± 0.03 | 0.01 ± 0.01 | Truncated at 4,096 tokens |
| NeuralCompiler | Compile error | 0.10 ± 0.03 | 0.34 ± 0.05 |

The Breakout compiler response references H1 unit `paddle_col_1` as an H2 output signal and fails with `KeyError`; it was not repaired or scored. The Asterix standalone response did not close its Python block or define a complete return before the token limit. Original model outputs are stored as `qwen38_*.txt`; complete Python blocks were extracted verbatim into `.py` files for evaluation. The evaluator makes the source snippets' short `ir` and `backend` import names available as aliases, and adapts the standalone Seaquest response's callable to the standard `forward` interface without changing its weights or behavior.

The model files live under `.local_models/qwen38-27b` and are ignored by Git. `scripts/restore_qwen38_for_eval.py` restores the locally referenced archive, and `scripts/run_qwen38_minatar.py` generates the raw outputs when run with a suitable vLLM environment and GPU. The weights occupy about 52 GiB; they are not included in the repository.
