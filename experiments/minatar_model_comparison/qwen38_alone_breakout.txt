## Design

**Strategy:** The ball moves diagonally at 1 cell/step. The paddle is 1 cell wide. To survive, the paddle must be at the ball's x-coordinate when the ball reaches row 9. Since the ball's x changes by ±1 each step, the paddle must track the ball's x exactly. The optimal policy is:
- If ball_x > paddle_x: move right
- If ball_x < paddle_x: move left  
- If ball_x == paddle_x: no-op (stay)

This is a simple "chase the ball" policy. With sticky actions (10% repeat), it's still near-optimal since the ball moves at most 1 cell/step and the paddle can match that.

**Hidden units:**
- **Unit 0 (h1):** Detects ball position (sum of ball channel)
- **Unit 1 (h1):** Detects paddle position (sum of paddle channel)
- **Units 2-11 (h1):** Ball column detectors (one per column 0-9)
- **Units 12-21 (h1):** Paddle column detectors (one per column 0-9)
- **Units 22-31 (h1):** Unused (zero)

**h2 units:**
- **Unit 0:** ball_x - paddle_x (positive if ball is right of paddle)
- **Unit 1:** paddle_x - ball_x (positive if ball is left of paddle)
- **Units 2-31:** Unused

**Output:**
- Logit[1] (left) = large if ball_x < paddle_x
- Logit[3] (right) = large if ball_x > paddle_x
- Logit[0] (no-op) = large if ball_x == paddle_x
- Others: very negative

The key insight: I need to compute the *difference* between ball and paddle x-positions. I'll use the column detectors to encode positions as weighted sums, then subtract.
